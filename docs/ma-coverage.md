# Managed Agents integration coverage

The API catalog lives in `shared/ma-contract.json` and `shared/ma.ts`. Each client calls registered operations directly on fixed public Volcano origins. No Open Muse backend or arbitrary upstream URL is used.

| Resource                    | Count | Scope                                                                                              |
| --------------------------- | ----: | -------------------------------------------------------------------------------------------------- |
| Agents                      |     6 | Create, list, view, update, delete, version history                                                |
| Environments                |     5 | Create, list, view, update, delete                                                                 |
| Sessions and events         |    11 | Session management, environment filtering, resource mounting, messages, history, and event streams |
| Memory                      |    12 | Memory libraries, creator filtering, memory management, batch writes                               |
| Connections and credentials |    13 | Vault, credential management and validation, OAuth providers and flows                             |
| Skills                      |     2 | ZIP upload, lookup by ID                                                                           |
| Files                       |     3 | Upload, metadata and download links, delete                                                        |

52 operations in total. Open Muse calls the data plane with an Ark API key. Control-plane (TOP) operations need Volcano console credentials, so Studio hides them and the client rejects them. Duplicate control-plane and data-plane entries are not shown twice.

## Usage

Daily conversations manage the Agent and Environment automatically. Only the advanced Studio requires editing path parameters, query parameters, or JSON request bodies. Write operations require confirmation, agent updates require a version, and deletion requires verifying the target ID.

Sessions can mount files and Vaults; tools, MCP, skills, and multi-agent configurations are executed by the upstream. The upload limit for files and skills is 10 MB; a skill package should contain `SKILL.md`. The app does not execute uploaded skill content locally.

MCP OAuth requires completing authorization in the external service. File downloads return links generated by the upstream; the client does not attach Ark credentials when opening those links. Treat temporary download links as sensitive URLs.

## Boundaries

- "Integrated" means adaptation code and entry points exist; it does not mean every account and environment has permission, nor that every operation has passed real-account acceptance.
- No operations or management interfaces are provided; unregistered operations return an error.
- Skill listing, updating, and deletion, plus memory version history entry points, are not currently provided.
- `self_hosted` configuration can be managed, but the app itself does not provide a corresponding runtime worker.
- Live streams live in the task details and are not served by the advanced JSON editor.
- The default cloud environment can access the public internet; agents created by the app default tool permissions to `always_allow`, executed directly by MA, and explicit upstream denials remain in effect. Old sessions may require a new task to use updated permissions.

Type descriptions for interface fields are only form hints and do not replace full upstream validation. Before updating the catalog, verify against the [Volcano Ark documentation](https://www.volcengine.com/docs/82379), permissions, and operation side effects, and add corresponding regression tests; new routes are not automatically enabled at runtime.
